# TrueFlag AI - security and reliability gap report

**Audit:** November 13, 2026; HEAD `a3b2ba4`. Local capstone assessment, not penetration testing, legal assurance or production certification. No remediation/source changes, live migration, permission changes, provider egress or destructive demo operations were performed.

## 1. Risk interpretation

- Priorities describe impact on a credible connected capstone and safe deployment, not CVSS scores or evidence of exploitation.
- Separate **tested application boundaries** from database-administrator authority, deployment configuration and workflows that do not exist.
- Current test counts and failures are recorded in [CURRENT_SYSTEM_AUDIT.md](CURRENT_SYSTEM_AUDIT.md#6-validation-ledger---november-13). Historical acceptance reports do not override a new failure.

|---|---|---|
| Authentication | Argon2; signed `sub/iat/exp/iss/aud`; expiry, invalid token, anonymous and inactive-user tests in `test_security_foundation.py` | No MFA/SSO/password-reset/server logout; no production identity review |
| Case authorization / IDOR | Current DB role; analysts restricted to assignment; supervisor/admin current workspace; `test_cases*.py`, API tests and browser cross-analyst/revocation cases | No team/tenant partition or PostgreSQL RLS; assignment UI missing |

| Concurrent writes | Unique idempotency receipts, conflict fingerprints, row/advisory locking, case version checks, SKIP LOCKED/fenced job claims | Tests prove named schedules, not all possible races or unlimited load |
| Atomicity | Assessment/explanation/job/audit and import chunks commit together; injected DB/audit failure tests | Prior committed chunks remain by design; not whole-file all-or-nothing semantics |
| Immutable scientific results | SHA-before-deserialization, approved fixed modules/runtime, original preprocessing/class mapping, independent SHAP reconstruction | Approved serialized artifact remains trusted code; no uploaded/untrusted model support |
| Evidence integrity | Immutable source/record versions, source-bound case membership, revision manifests/cursors, independent numeric oracle tests | Integrity is not completeness/truth of a bank's source records; no arbitrary CSV-to-evidence retrofit |
| Investigation containment | Bounded jobs/retries/leases; minimized provider input, fixed DSL, no tools, clean subprocess environment; draft tamper/recovery tests | Fake-only behavior; no real provider/network/semantic risk acceptance |

## 5. Audit execution safeguards

- Full Linux/PostgreSQL tests and browser workers use a **previously created recoverable clone**, fresh disposable schemas and synthetic fixtures. Live demo checks were health requests and aggregate SELECTs only.
- Scientific replays mount pinned private model/reference assets read-only, with bounded Linux runtime. No model training, reference rewriting or provider access.
- Local tooling needed approved access outside the restrictive sandbox for Docker/Chromium/esbuild. An initial frontend startup denial was rerun successfully; no automatic-approval rejection is outstanding.
- No dependency installation, remote CVE/CI check, new load/chaos exercise against the running demo, public publish or Git push.
- Source/dirty-file/environment/scientific-asset fingerprints are checked before completion. Six new audit documents are the only intended source-tree additions.

## 6. Release gate

Do not call the current system production-ready. A minimum promotion gate requires: explain/retest current failures; aligned release/schema; recoverable migration and restore; restricted DB role; connected evidence with honest feature provenance; complete human action history; real-provider and regulatory approvals/evaluations for any corresponding demo claim.
