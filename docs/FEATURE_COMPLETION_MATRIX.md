## Cross-cutting interpretation

- Data constraints/IDs and saved prediction parity support reproducibility, not completeness of financial history or real-world AML effectiveness.
- F18 generated cases can be structurally connected through F22/F23 in backend tests. The current F10 CSV path supplies declared predictors only and has no supported transaction-evidence binding step.
- F23 verification is functional backend software around a **simulated model**. It must not be marketed as real LLM reasoning, factual entailment or legal interpretation.
- F28/F29 are human gates; F24, investigation HTTP/UI and F30-F32 are engineering gaps. Approvals alone cannot implement missing adapters/screens, and code alone cannot grant approvals.
- Empty tables, raw DTO fields, historical roadmaps and passing mock component tests are not treated as proof of completed user workflows.
